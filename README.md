# kimi-remote-shell

Перенаправление shell-команд [Kimi Code](https://www.kimi.com/code) на удалённую машину по SSH
с опциональной двусторонней синхронизацией файлов через [Mutagen](https://mutagen.io).
Полный аналог [torarnv/claude-remote-shell](https://github.com/torarnv/claude-remote-shell) для Kimi Code.

- **Разгрузите локальную машину** — сборки, тесты и долгие команды выполняются на удалённом хосте
- **Используйте более мощное железо** — направьте Kimi на производительный сервер, сохранив локальный редактор, MCP-инструменты и настройки
- **Без лагов UI** — сам Kimi и все файловые операции остаются локальными
- **Смягчите разрешения для shell** — если удалённый хост — выделенная VM, `-yolo` безопасен для локальной машины

## Установка

```sh
# Homebrew (ставит и mutagen)
brew install Kovami/kimi-remote-shell/kimi-remote-shell

# или одной командой без brew (macOS/Linux)
curl -fsSL https://raw.githubusercontent.com/Kovami/kimi-remote-shell/main/install.sh | bash
```

Плагин Kimi ставится и обновляется автоматически при запуске `kimi-remote-shell`.
Для curl-варианта `mutagen` нужно поставить самому; команды линкуются в `~/.local/bin`
(повторный запуск команды обновляет установку, `KRS_REF=v0.1.0` — закрепить версию).
Из клона репозитория: `./install.sh` (только плагин).

Требования: `mutagen`, `node`, SSH-доступ к удалённому хосту по ключу.

## Использование

```sh
# Только удалённое выполнение (без синка проекта)
kimi-remote-shell [user@]host

# Удалённое выполнение + синк текущей директории на удалённый путь
kimi-remote-shell [user@]host:/path/on/remote

# Дополнительные опции kimi пробрасываются
kimi-remote-shell user@host:/path --model kimi-code/k3

# Авто-аппрув всех инструментов (для доверенной VM)
kimi-remote-shell-yolo user@host:/path
```

Kimi запускается как обычно, но все shell-команды выполняются на удалённом хосте.
Файловые инструменты (Read/Write/Edit/Grep/Glob) работают локально; Mutagen синхронизирует
проект в обе стороны, с flush до и после каждой команды. Пути автоматически
транслируются в обе стороны — в тексте команд и в выводе.

## Как это устроено

В отличие от Claude Code, у Kimi Code нет переменной типа `CLAUDE_CODE_SHELL` (путь к shell
захардкожен), поэтому вместо перехвата используется **замена** штатными механизмами Kimi:

1. **Плагин** (`plugin/`) объявляет MCP-сервер `remote-shell` с инструментом
   `mcp__plugin-kimi-remote-shell_remote-shell__bash` — зеркалом встроенного Bash
   (те же параметры: `command`, `cwd`, `timeout`, `run_in_background`, `description`).
2. **Хук** `PreToolUse(Bash)` блокирует встроенный Bash и перенаправляет агента на MCP-инструмент
   (только когда выставлен `KIMI_REMOTE_HOST`; в обычных сессиях плагин не мешает).
3. **Хук** `UserPromptSubmit` на первом промпте внедряет контекст об удалённом окружении.
4. **Лончер** поднимает сессионную tmpdir, SSH ControlMaster, изолированный mutagen-демон,
   синк проекта — и всё это сносит при выходе.

Отличия от оригинала: у фоновых задач нет автоматических уведомлений о завершении
(агент опрашивает `...__task_output`); синк tmpdir не нужен, т.к. Kimi передаёт `cwd`
параметром каждого вызова.

## Кастомизация синка

Создайте `.kimi-code/remote-shell/mutagen.yml` в проекте — он будет передан в
`mutagen sync create` через `-c` (например, для исключения `node_modules`).

## Ограничения

- Трансляция путей работает только на тексте команд и вывода; файлы с абсолютными путями
  внутри (например, `.git` файл git worktree) синкются как есть.
- При таймауте foreground-команды локальный ssh-процесс убивается, но удалённый процесс
  может продолжить работу (как и в оригинале).

План разработки и разбор оригинала — в [PLAN.md](PLAN.md).
